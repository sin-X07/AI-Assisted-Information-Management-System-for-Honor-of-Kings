# 《王者荣耀》信息管理系统 - 测试用例文档

**测试版本:** v2.0.0（GUI + SQLite + Web 可视化）  
**编写日期:** 2026-06-09  
**测试核心目标:** 验证控制台模式与 GUI 模式双系统在异常输入下的防崩溃兜底、角色权限控制、SQLite 数据持久化、Web 可视化仪表盘及操作日志记录。

---

## 测试环境与前置条件

### 硬件/软件环境

- JDK 17 或更高版本
- Maven 3.6+
- 系统终端支持 UTF-8 编码
- 浏览器（用于 Web 可视化测试）

### 构建与运行方式

#### Maven 构建（推荐，用于 GUI 模式）

```powershell
mvn clean package -DskipTests
java -jar target/hok-info-management-2.0.0.jar
```

#### 控制台模式（独立编译运行）

```powershell
javac -d out -encoding UTF-8 src/Main.java src/model/*.java src/util/*.java src/service/*.java
java -cp out Main
```

### 测试数据集

- **数据规模**: 90 英雄 / 88 装备 / 20 战队 / 70+ 玩家（含 1200+ 对局记录）
- **默认管理员账号**: `admin` / 密码: `123456`
- **默认普通玩家账号**: `player` / 密码: `123456`
- **测试数据生成**: `DataInitializer.initializeHeroes()` / `initializeEquipments()` / `initializeTeams()` / `initializePlayers()`

### 关键验证数据

- 英雄 H001（李白）：定位打野/刺客，推荐装备 E005/E006/E007 共 3 件
- 英雄 H031（武则天）：中路法师，推荐装备 E031/E032/E036
- 玩家 `花海`：15 场对局 12 胜（胜率 80%），所属战队 eStarPro (T003)
- 玩家 `一诺`：14 场对局 11 胜（胜率约 78.6%），所属战队 AG (T002)
- 战队 T003（武汉 eStarPro）：队长 花海，胜率 74%，130 总场次

## 测试用例矩阵 (Test Case Matrix)

### TC-01: 身份认证安全防护 — 错误凭证拦截

**测试目的:** 验证系统对非授权或错误凭证的拒绝能力，以及登录循环的恢复能力。  
**适用模式:** 控制台 + GUI  
**输入序列（控制台）:**  
  `wrong` → `bad` → `admin` → `123456`  
**预期输出:**  

  1. 错误凭证后打印：`用户名或密码错误，或账号状态不可用，请重试。`  
  2. 界面不退出、不崩溃，回到登录界面  
  3. 正确凭证后打印：`登录成功，欢迎系统管理员！` 或进入主界面  

**GUI 验证:**  

  1. 输入错误凭证时弹出 `JOptionPane.ERROR_MESSAGE` 提示  
  2. 输入正确凭证后关闭登录对话框，打开 MainFrame

### TC-02: 核心菜单交互健壮性 — 非法数字与字符兜底

**测试目的:** 拦截可能引发 `NumberFormatException` 的恶性输入。  
**适用模式:** 控制台  
**输入序列:** 在菜单选择时输入 `abc`  
**预期输出:**  

  1. `InputHelper.readInt()` 捕获 `NumberFormatException`，不抛出堆栈跟踪  
  2. 控制台打印：`请输入有效的整数。`  
  3. 程序不退出，继续等待合法输入

### TC-03: 编号检索英雄 — 中文编码隔离验证

**测试目的:** 验证通过英数字 ID（`H001`）能成功检索到实体。  
**适用模式:** 控制台 + GUI  
**输入序列（控制台）:** 菜单 `4` → 输入 `H001`  
**预期输出（控制台）:**  

- `李白：青莲剑仙；`  
- `定位：打野，类型：刺客`  
- `推荐召唤师技能：惩击`  

**GUI 验证:**  

- 英雄面板 JTable 中搜索 `H001` 或 `李白`，筛选后显示对应记录  
- 双击行弹出 HeroDetailDialog，显示完整英雄属性

### TC-04: 玩家详情级联查询 — 从玩家到战队到英雄到装备

**测试目的:** 验证 `displayPlayerDetails` 的级联查询链路完整性。  
**适用模式:** 控制台 + GUI  
**输入序列（控制台）:** 菜单 `7` → 输入 `花海`  
**预期输出（控制台）:**  

  1. 打印玩家 ID 和昵称（花海）  
  2. 打印所属战队：`武汉eStarPro (eStarPro)`，胜率 `74.0%`  
  3. 打印战队常用英雄列表（含定位/类型/难度/推荐装备）  
  4. 战队荣誉：`KPL知名战队，多冠战队代表`  

**GUI 验证:**  

- 玩家查询面板输入 `花海`，显示完整的四级级联信息

### TC-05: 玩家荣誉排行榜 — 双重降序与对齐排版

**测试目的:** 验证排行榜排序逻辑和中英文对齐。  
**适用模式:** 控制台 + GUI  
**输入序列（控制台）:** 菜单 `8` → 输入 `5`  
**预期输出:**  

  1. 标题 `===== 玩家荣誉排行榜 TOP 5 =====`  
  2. 第一名应为 `花海`（胜率 80%，15 场）或 `一诺`（约 78.6%）  
  3. 所有列对齐，中英文混排不偏移  

**GUI 验证:**  

- 排行榜面板显示 JTable，列宽合理，排序与控制台一致

### TC-06: 排行榜边界处理 — topN 边界值

**测试目的:** 验证非法 topN 值不导致崩溃。  
**适用模式:** 控制台  
**输入序列 1:** 菜单 `8` → 输入 `0`，预期无输出直接返回  
**输入序列 2:** 菜单 `8` → 输入 `100`，预期仅显示实际玩家总数  
**GUI 验证:**  

- 排行榜面板默认显示全部玩家，无输入边界问题

### TC-07: 导出排行榜到文件 — UTF-8 编码 + try-with-resources

**测试目的:** 验证 `FileStorageService` 正确导出 UTF-8 文件。  
**适用模式:** 控制台 + GUI  
**输入序列（控制台）:** 管理员登录 → 菜单 `10` → 输入 `ranking.txt`  
**预期输出（控制台）:**  

  1. `排行榜已成功导出到: ranking.txt`  
  2. `ranking.txt` 文件 UTF-8 编码，排序与控制台一致  
**GUI 验证:**  

- 点击侧边栏"导出排行榜"按钮，弹出文件保存对话框  
- 导出的文件内容与排行榜面板一致

### TC-08: 角色权限控制 — admin 拥有全部功能

**测试目的:** 验证管理员拥有全部数据操作权限。  
**适用模式:** 控制台 + GUI

  2. 可进入子菜单进行 CRUD 操作  

**GUI 验证:**  

  1. 侧边栏显示所有 9 个按钮（含数据管理）  
  2. 数据管理面板可进行增删改操作

### TC-09: 角色权限控制 — player 受限访问

**测试目的:** 验证普通玩家仅能浏览/查询。  
**适用模式:** 控制台 + GUI  
**预期输出（控制台）:**

  2. 输入 `9` → `请输入 0 到 8 之间的数字。`  

**GUI 验证:**  

  1. 侧边栏隐藏"数据管理"和"导出排行榜"按钮

### TC-10: 数据管理子菜单 — CRUD 完整闭环

**测试目的:** 验证添加→查询→更新→删除全流程。  
**适用模式:** 控制台 + GUI  
**输入序列（控制台 admin）:**  
  菜单 `9` → `1`（添加英雄）→ ID `H999`，名称 `测试英雄` → ...  
  菜单 `9` → `7`（更新英雄）→ ID `H999` → ...

**预期输出:**  

  1. 添加成功：`英雄 [测试英雄] 添加成功。`  
  2. 更新成功：`更新成功。`  
  3. 删除成功：`删除成功。`  
**GUI 验证:**  

- 数据管理面板表单提交后，英雄面板 JTable 同步刷新  
- 详情对话框可正常打开，编辑后保存生效

### TC-11: 退出登录生命周期

### TC-17: Web 可视化服务器启动

**测试目的:** 验证 VisualizationServer 能正常启动并返回 JSON 数据。  
**适用模式:** GUI  
**测试步骤:**  

  1. 管理员登录 → 点击侧边栏"数据可视化"  
  2. 观察浏览器自动打开  

**预期结果:**  

  1. 控制台输出 `Visualization server started at http://localhost:XXXXX`  
  2. 浏览器显示 ECharts 仪表盘页面  
  3. 各图表正常渲染（英雄位置分布、类型分布、能力雷达、难度分布、装备价格、战队胜率）

### TC-18: Web 模糊搜索 API

**测试目的:** 验证 VisualizationServer 的模糊搜索端点。  
**适用模式:** GUI  
**测试步骤:**  

  1. VisualizationServer 启动后（以端口 12345 为例）  
  2. 浏览器访问 `http://localhost:12345/api/heroes/search?q=李白`  

**预期结果:**  

  1. 返回 JSON 格式，包含英雄李白的信息  
  2. `heroes[0].heroName` = `"李白"`  
  3. `heroes[0].score` > 0.4（模糊搜索权重）  
  4. 搜索 `白` 也能返回李白（子串匹配）

### TC-19: 操作日志记录

**测试目的:** 验证 CRUD 操作被正确记录。  
**适用模式:** GUI  
**测试步骤:**  

  1. 管理员登录 → 数据管理 → 执行至少一次添加/编辑/删除操作  
  2. 观察 `logs/` 目录下的日志文件  
  3. 检查 SQLite 数据库的 operation_logs 表  

**预期结果:**  

  1. SLF4J 日志文件包含 `操作日志: [时间] ...` 格式的记录  
  2. SQLite 数据库中 operation_logs 表存在对应记录  
  3. 操作类型（ADD/UPDATE/DELETE）、目标类型（HERO/EQUIPMENT/TEAM）、操作结果（成功/失败）正确记录
