# 《王者荣耀》信息管理系统 - 自动化流与健壮性测试用例文档

**测试版本:** v1.3.0 (Stage 5-6 整合修正版)  
**测试编写日期:** 2026-06-07  
**测试核心目标:** 验证系统在异常键盘输入下的防崩溃兜底能力、多权限登录路由、以及新增的"玩家独立战绩"多维兼容查询。

---

## 测试环境与前置条件

1. **测试数据集 (DataInitializer 提供):**
   - 默认管理员账号: `admin` / 密码: `123456`
   - 默认普通玩家账号: `player` / 密码: `123456`（角色为 PLAYER）
   - 离散初始数据: 3个战队、15名玩家、15个英雄（双向绑定装备）、22件基础装备。
   - 关键验证数据:
     - 英雄 `H001`（李白）：定位打野/刺客，推荐装备 E005/E006/E007 共 3 件
     - 玩家 `花海`：15 场对局 12 胜（胜率 80%），所属战队 eStarPro
     - 玩家 `一诺`：14 场对局 11 胜（胜率约 78.6%），所属战队 AG
     - 玩家 `Fly`：12 场对局 9 胜（胜率 75%），所属战队 重庆狼队
2. **测试机制:** 采用标准输入流（PowerShell Pipeline）进行断点黑盒模拟，杜绝手动输入带来的随机性误差。
3. **字符编码:** 项目源文件为 UTF-8 编码，编译时必须加 `-encoding UTF-8`。

## 测试用例矩阵 (Test Case Matrix)

### TC-01: 身份认证安全防护 — 错误凭证拦截

**测试目的:** 验证系统对非授权或错误凭证的拒绝能力，以及登录循环的恢复能力。  
**输入序列 (共 4 行):**  
  `wrong` → 错误的用户名  
  `bad`  → 错误的密码（此时无对应匹配）  
  `admin` → 正确的管理员用户名  
  `123456` → 正确的管理员密码  
**预期输出:**  

  1. 第一组错误凭证后，控制台打印：`用户名或密码错误，或账号状态不可用，请重试。`  
  2. 界面不退出、不崩溃，自动回到登录提示 `===== 用户登录 =====`  
  3. 第二组正确凭证后，打印：`登录成功，欢迎系统管理员！`  
  4. 随后进入管理员主菜单（含 10 项功能选项）  
**断言依据:** `AuthenticationService.login()` 对不匹配的账号返回 `null`，`Main.loginLoop()` 在 `null` 时打印上述错误消息并循环。

### TC-02: 核心菜单交互健壮性 — 非法数字与字符兜底

**测试目的:** 拦截可能引发 `NumberFormatException` 的恶性输入。  
**输入序列:** 在菜单选择提示时输入 `abc`  
**预期输出:**  

  1. `InputHelper.readInt()` 捕获 `NumberFormatException`，不抛出任何堆栈跟踪。  
  2. 控制台打印防错提示：`请输入有效的整数。`  
  3. 程序不退出，继续等待用户重新输入合法的菜单数字。  
**断言依据:** `InputHelper.readInt()` 的 while 循环内 `catch (NumberFormatException e)` 分支。

### TC-03: 编号检索英雄 — 中文编码隔离验证

**测试目的:** 验证在管道传输中文可能有损耗的场景下，通过英数字 ID（`H001`）能成功检索到实体。  
**输入序列:** 菜单选择 `4`（查询英雄），然后输入 `H001`  
**预期输出:**  

  1. 系统通过 `GameDataManager.findHeroById("H001")` 定位到英雄李白。  
  2. 控制台打印：  
     - `李白：青莲剑仙；`  
     - `定位：打野，类型：刺客`  
     - `推荐召唤师技能：惩击`  
     - `简介：高机动刺客, 适合切入后排。`  
**断言依据:** 主菜单选项 4 对应 `searchHero()`，内部先 `findHeroByName` 再 `findHeroById` 兜底。

### TC-04: 玩家详情级联查询 — 从玩家到战队到英雄到装备

**测试目的:** 验证 `displayPlayerDetails` 的级联查询链路完整性。  
**输入序列:** 菜单选择 `7`（玩家详情查询），输入 `花海`  
**预期输出:**  

  1. 打印玩家ID和昵称（花海）  
  2. 打印所属战队信息：`武汉eStarPro (eStarPro)`，胜率 `74.0%`，教练 `SK`，队长 `花海`  
  3. 打印战队常用英雄列表：韩信、貂蝉、吕布、后羿、蔡文姬，每位英雄含定位/类型/难度/推荐装备  
  4. 战队荣誉行：`KPL知名战队, 多冠战队代表`  
**断言依据:** `GameDataManager.displayPlayerDetails()` 通过 `memberNames` 反查 `Team`，遍历 `mainHeroes` 再查 `Hero` 和 `Equipment`。

### TC-05: 玩家荣誉排行榜 — 双重降序与对齐排版

**测试目的:** 验证排行榜的排序逻辑（胜率→总场次双重降序）和控制台中文对齐。  
**输入序列:** 菜单选择 `8`（玩家荣誉排行榜），输入 `5`  
**预期输出:**  

  1. 标题 `===== 玩家荣誉排行榜 TOP 5 =====`  
  2. 表头含：排名、ID、昵称、战队、胜率、总场次  
  3. 排名第一名应为 `花海`（胜率 80%，15 场），或 `一诺`（约 78.6%，14 场）  
  4. 所有列对齐，中英文混排不偏移，数值列右对齐  
**断言依据:** `RankingService.displayTopPlayers()` 使用 `.comparingDouble(winRate).thenComparingInt(totalMatches).reversed()`，并用 `formatWithChinese()` 处理中文字符宽度。

### TC-06: 排行榜边界处理 — topN ≤ 0 安全跳过

**测试目的:** 验证非法 topN 值不导致崩溃。  
**输入序列 1:** 菜单选择 `8`，输入 `0`  
**预期输出:** 无任何输出，直接返回主菜单（`topN <= 0` 时 `return`）  
**输入序列 2:** 菜单选择 `8`，输入 `100`（超过 15 名玩家总数）  
**预期输出:** 仅显示 15 名玩家，`TOP 15`

### TC-07: 导出排行榜到文件 — UTF-8 编码 + try-with-resources

**测试目的:** 验证 FileStorageService 能正确导出排序后的排行榜。  
**输入序列:** 菜单选择 `10`（导出排行榜，仅管理员可见），输入 `ranking.txt`  
**预期输出:**  

  1. 控制台打印：`排行榜已成功导出到: ranking.txt`  
  2. 磁盘生成 `ranking.txt`，UTF-8 编码，表头行 + 分隔行 + 15 行数据  
  3. 文件内容排序与 TC-05 屏幕输出一致（胜率→总场次双重降序）  
**断言依据:** `FileStorageService.exportRankingToFile()` 使用 `try-with-resources` + `StandardCharsets.UTF_8`，复用 `RankingService` 的 Comparator。

### TC-08: 角色权限控制 — admin 拥有全部功能

**测试目的:** 验证 admin 登录后菜单包含 10 项（含数据管理和导出）。  
**输入序列:** 以 `admin` / `123456` 登录  
**预期输出:**  

  1. 登录后菜单上限为 `[0-10]`  
  2. 控制台逐行打印：`9. 数据管理（增删改）` 和 `10. 导出排行榜到文件`  
  3. 可进入子菜单（输入 9），显示增删改 9 项操作

### TC-09: 角色权限控制 — player 受限访问

**测试目的:** 验证普通玩家登录后仅能浏览/查询，无增删改和导出权限。  
**输入序列:** 以 `player` / `123456` 登录  
**预期输出:**  

  1. 登录后菜单上限为 `[0-8]`  
  2. 菜单中不出现第 9、10 项  
  3. 尝试输入 `9` → 控制台提示 `请输入 0 到 8 之间的数字。`  
  4. 玩家可使用功能 1-8（查看列表、查询、排行榜）

### TC-10: 数据管理子菜单 — 增删改 CRUD 完整闭环

**测试目的:** 验证管理员能完整执行添加→查询→更新→删除全流程。  
**输入序列 (admin 登录后):**  
  菜单 `9` → 子菜单 `1`（添加英雄）→ ID `H999`，名称 `测试英雄`，其他填入测试值  
  菜单 `9` → 子菜单 `7`（更新英雄）→ ID `H999`，回车跳过保留原值  
  菜单 `9` → 子菜单 `4`（删除英雄）→ ID `H999`  
**预期输出:**  

  1. 添加成功提示：`英雄 [测试英雄] 添加成功。`  
  2. 更新时展示旧值，回车保留后提示 `更新成功。`  
  3. 删除成功提示：`删除成功。`

### TC-11: 流结束保护 — 退出登录与生命周期闭环

**测试目的:** 验证退出登录及程序的资源优雅释放。  
**输入序列:** 任意合法登录后 → 菜单 `0`（退出登录）  
**预期输出:**  

  1. 控制台打印：`已退出当前账号。`  
  2. 自动回到登录界面 `===== 用户登录 =====`  
  3. 可重新登录，不出现内存泄漏或流断开异常  
**断言依据:** `mainMenuLoop` 中 `case 0` 设置 `loggedIn = false`，退出内层循环后 `main` 的 `while(true)` 重新调用 `loginLoop()`。
